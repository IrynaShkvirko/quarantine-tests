**Context.** Sets up the backend's structure, configuration, logging, health checks, database access and job queue, so feature tasks only add code in the right folder.

**Implementation**

1. Package layout under `backend/app/` exactly as §7: `api/`, `domain/`, `integrations/`, `workers/`, `jobs/`, `db/`, `config/`, `admin/`, each with `__init__.py`.
2. `app/settings.py`: one `Settings(BaseSettings)` class with `env_prefix="FQ_"`: `database_url`, `env` (`local|ci|prod`), `log_level`, `ingest_max_upload_mb` (default 50). Loaded once through a cached `get_settings()`.
3. `app/logging.py`: structlog configured for JSON output in `prod`/`ci` and readable console output in `local`; a request-ID middleware that adds `request_id` to every log line and the `X-Request-ID` response header.
4. `app/db/session.py`: async SQLAlchemy engine (`postgresql+psycopg://`), `async_sessionmaker`, a FastAPI dependency yielding a session per request; `app/db/base.py` with the declarative `Base` and a naming convention for constraints (so Alembic names are stable).
5. Alembic in `backend/alembic/` with async `env.py` that reads `FQ_DATABASE_URL` and targets `Base.metadata`; first empty revision `0001_baseline`.
6. `app/api/health.py`: `GET /healthz` (process alive, no DB), `GET /readyz` (runs `SELECT 1` and checks the Procrastinate schema exists; 503 if not), `GET /metrics` (prometheus-client, plus HTTP request count and latency by route via middleware).
7. `app/workers/queue.py`: Procrastinate `App` with `PsycopgConnector` on the same database; a `ping` task used only by tests; `worker` entrypoint in `app/__main__.py` (`python -m app worker`). Procrastinate's schema is applied by an Alembic migration, not at runtime.
8. `app/main.py`: `create_app()` factory wiring routers, middleware, lifespan (open/close the engine and the Procrastinate connector).
9. `app/admin/cli.py`: `fq-admin` entrypoint (Typer) with a `version` command; later tasks add commands.
10. Test setup in `backend/tests/`: `conftest.py` that creates a fresh schema in `fq_test` per test session via Alembic, a transactional session fixture rolled back after each test, an `httpx.AsyncClient` fixture on the app. Mark DB tests `@pytest.mark.integration`.

**Out of scope.** Any real table (M0-09), any business endpoint.

**Acceptance criteria**

- [ ] `alembic upgrade head` and `alembic downgrade base` both work on an empty database.
- [ ] `/healthz` returns 200 without a database; `/readyz` returns 503 when the DB is down and 200 when it's up.
- [ ] `/metrics` exposes request count and latency by route.
- [ ] A test defers the `ping` task, a worker runs it, and the test sees it completed.
- [ ] Logs are JSON in `ci` and include `request_id`.

**Tests.** Unit tests for settings and logging; integration tests for `/readyz`, the queue round-trip and the migration up/down.
