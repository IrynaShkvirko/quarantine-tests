**Question.** For pytest, Playwright and Jest, can we get every attempt of a rerun test (outcome, duration, failure message) into JUnit XML, and what must our reporters add? Rerun evidence is the main detection signal, so this decides the plugin design.

**What to try** (in `spikes/rerun-attempts/`, one tiny project per framework, each with 1 stable test, 1 test that fails then passes, 1 test that always fails, 1 parametrized flaky test):

1. **pytest** with `pytest-rerunfailures --reruns 2` and `--junitxml`. Check what the XML contains for a rerun test: only the final result, extra elements per rerun, or properties. Then write a 30-line `conftest.py` hook (`pytest_runtest_logreport`) that records each attempt and adds `fq.attempt` properties or one `<testcase>` per attempt.
2. **Playwright** with `retries: 2`, reporters `junit` and `json` side by side. Check whether the JUnit output shows retries and flaky status, and what `results[]` in the JSON reporter holds per retry. Prototype a custom reporter (`onTestEnd` receives each attempt's `TestResult` with `retry`) that writes our JUnit format.
3. **Jest** with `jest.retryTimes(2, { logErrorsBeforeRetry: true })` and `jest-junit`. Check what `jest-junit` writes, and what a custom reporter's `onTestCaseResult` / test results expose about retries (look for invocation counts and retry reasons in the installed Jest version). Prototype a reporter that writes our format.
4. For each framework, note the test name and file fields we need for the §3.1 test key, including parametrized names and nested `describe` titles.

**Deliverable**

- `docs/spikes/rerun-attempts.md`: a table per framework (native support / what's missing / chosen approach / effort), plus edge cases found.
- Sample XML files for each framework copied to `docs/contracts/examples/`.
- Prototype reporter code kept in `spikes/` as the starting point for M1-06, M5-01, M5-02.

**Decision to record.** One attempt representation for all three frameworks (one `<testcase>` per attempt with `fq.attempt`, or native elements) and the JUnit conventions table in M0-08 updated to match.

**Acceptance criteria**

- [ ] For each framework, a sample XML shows all 3 attempts of the fails-twice test with outcome, duration and message.
- [ ] Findings doc lists any case where attempt data can't be captured, with the fallback.
- [ ] M0-08 conventions updated and agreed.
