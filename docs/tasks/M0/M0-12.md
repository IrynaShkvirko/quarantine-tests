**Question.** Can a GitHub App open a PR that changes only `quarantine.yaml` and have it merge automatically once the required check passes, without a human review, while every other PR on `main` still needs a review? Automatic quarantine depends on this.

**What to try** (on a scratch repo `fq-sandbox` under your account):

1. Create a GitHub App `fq-bot-dev` with permissions `contents: write`, `pull_requests: write`, `metadata: read`, `checks: read`, and webhook events `pull_request`, `push`. Install it only on `fq-sandbox`. Store the private key outside the repo.
2. Rulesets on `main`, split so the bypass applies to review only:
   - **Ruleset A "review":** require a pull request with 1 approving review. Bypass list: the App, in pull-request-only bypass mode.
   - **Ruleset B "checks":** require status check `fq-quarantine-check`. No bypass for anyone.
3. A minimal `fq-quarantine-check` workflow that passes only if the PR changes exactly `quarantine.yaml` (`git diff --name-only origin/main...HEAD`).
4. A 50-line Python script that authenticates as the App (JWT → installation token), creates a branch, commits a change to `quarantine.yaml`, opens a PR, and enables auto-merge (GraphQL `enablePullRequestAutoMerge`, squash).
5. Scenarios to run and record:
   - App PR changing only `quarantine.yaml` → expected: check passes and the PR auto-merges with no review.
   - App PR also changing `README.md` → expected: check fails, no merge.
   - Human PR changing only `quarantine.yaml` → expected: still needs a review.
   - App PR when the check fails → expected: stays open.
6. If auto-merge doesn't honour the bypass, try the fallback: the App waits for the check (webhook `check_suite` completed) and merges through the REST merge endpoint itself. Record which one works.

**Deliverable**

- `docs/spikes/github-app.md`: App manifest (permissions and events), ruleset JSON exported from the API, the scenario results table, the chosen merge method, and step-by-step setup for a new repo.
- The prototype script in `spikes/github-app/`, the starting point for M3-01.

**Decision to record.** Auto-merge or App-driven merge, and the exact ruleset layout to require in user repos (§9.5 updated if it differs).

**Acceptance criteria**

- [ ] All four scenarios run and behave as expected (or the difference is documented with the fallback that works).
- [ ] Setup steps are complete enough to repeat on a second repo in under 15 minutes.
- [ ] No private key or token is committed (checked by the `detect-private-key` hook).
