**Question.** Given a list of test keys from `quarantine.yaml`, can each framework (a) run everything except those tests and (b) run only those tests, exactly, without the excluded ones showing up as "skipped"? This decides how the blocking job and the quarantine job select tests.

**What to try** (in `spikes/select-tests/`, using a fixture list of 20 test keys that includes the hard cases below):

1. **pytest:** a plugin hook `pytest_collection_modifyitems` that maps each item to its §3.1 key and moves matching items to `config.hook.pytest_deselected` (exclude) or keeps only them (only). Confirm deselected tests don't appear in JUnit.
2. **Playwright:** build `grep` / `grepInvert` regexes from full titles in `playwright.config.ts` (read the YAML there). Also check whether the installed Playwright version has a way to pass an explicit list of tests (a test-list file option or similar), which would avoid regex escaping.
3. **Jest:** exclusion with `-t` using a negative-lookahead regex of full names; inclusion with `--testPathPattern` + `-t`. Check whether a custom `testSequencer` or test environment could do it more cleanly, and whether those approaches report excluded tests as skipped.
4. **Hard cases to include in the fixture list:**
   - parametrized pytest IDs with brackets, spaces, unicode and `::` inside parameters;
   - Playwright and Jest titles with regex characters (`( ) [ ] . * + ? $ ^ |`), quotes and `>`;
   - nested `describe` blocks and two tests with the same title in different files;
   - a list of 300 keys (to hit command-line length limits; pass the list through a file or environment variable instead).
5. Measure the overhead of each approach on a 500-test suite (collection time with and without the filter).

**Deliverable**

- `docs/spikes/select-tests.md`: approach per framework, how each hard case behaves, limits and overhead numbers.
- Prototype code in `spikes/select-tests/` reused by M3-08, M5-01, M5-02.

**Decision to record.** The selection mechanism per framework, and how the list reaches it (always a file path in `FQ_QUARANTINE_FILE`, never inline on the command line).

**Acceptance criteria**

- [ ] For each framework, exclude mode runs exactly the 480 non-listed tests of the 500 and only mode runs exactly the 20 listed ones, including every hard case.
- [ ] Excluded tests don't appear as skipped in the JUnit output.
- [ ] Overhead on 500 tests is measured and written down.
