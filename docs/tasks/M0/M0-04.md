**Context.** This is CI for the flaky-quarantine project itself, not the reusable workflow it ships to other repos. Agents open many PRs; each must be checked automatically before you review it.

**Implementation**

1. `.github/workflows/project-ci.yml`, triggered on `pull_request` and `push` to `main`, with `concurrency` cancelling older runs of the same branch.
2. Jobs:
   - **python:** `astral-sh/setup-uv`, `uv sync --frozen`, `make lint`, `make typecheck`, `pytest` with coverage for `backend`, `plugins/pytest-flaky-reporter`, `ci/fq-cli`. Upload `coverage.xml` as an artifact.
   - **node:** `pnpm/action-setup` + `actions/setup-node` (22, pnpm cache), `pnpm install --frozen-lockfile`, `pnpm -r lint`, `pnpm -r typecheck`, `pnpm -r test`.
   - **integration** (added empty now, filled from M0-06): a `postgres:16` service container, `alembic upgrade head`, `pytest -m integration`.
   - **docker:** build the backend image from `backend/Dockerfile` (created in M0-05) with BuildKit cache; no push yet.
   - **pre-commit:** `pre-commit run --all-files` so local hooks can't be skipped.
3. Path filters with `dorny/paths-filter` so a docs-only PR skips python, node and docker jobs; a final `ci-ok` job depends on all jobs and always runs, so branch protection needs only one required check.
4. Branch protection (or a ruleset) on `main`: require PR, require `ci-ok`, require linear history, block force-push. Write the settings in `docs/CONTRIBUTING.md` so they can be recreated.
5. Dependabot config for `uv`, `npm` and `github-actions`, weekly, grouped minor/patch updates.

**Out of scope.** Publishing packages or images (M6), the reusable workflow for user repos (M1-07).

**Acceptance criteria**

- [ ] A PR runs all jobs and finishes in under 10 minutes on a cold cache.
- [ ] A docs-only PR finishes in under 2 minutes and `ci-ok` is green.
- [ ] A deliberately failing test or lint error turns `ci-ok` red and blocks merge.
- [ ] `main` cannot be pushed to directly.
