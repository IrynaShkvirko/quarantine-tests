**Context.** The ingestion API is the contract between three framework plugins, two CI systems and the backend. Writing it down first lets plugin and backend work run in parallel.

**Implementation**

1. `docs/contracts/ingestion.md` covering:
   - **Request:** `POST /api/v1/ingest/runs`, `Authorization: Bearer <repo token>`, `multipart/form-data` with one `metadata` part (JSON) and one or more `junit` parts (XML files, each ≤ the configured size, total ≤ `FQ_INGEST_MAX_UPLOAD_MB`). Gzip allowed per part (`Content-Encoding: gzip` on the part).
   - **Responses:** `202 {upload_id}`, `400` (schema or XML error, body lists problems), `401` (bad token), `409` never (duplicates are accepted and ignored), `413` (too large), `429` (rate limited, with `Retry-After`).
   - **Idempotency key:** `(repository, ci_system, run_id, run_attempt, shard, job_kind, framework)`. A second upload with the same key returns 202 with the first `upload_id`.
   - **Status:** `GET /api/v1/ingest/runs/{upload_id}` → `queued | parsed | failed` + error summary.
2. `docs/contracts/metadata.schema.json` (JSON Schema draft 2020-12) for the metadata object in §8.2: required fields, enums for `ci_system`, `event`, `job_kind`, `framework`; `shard` pattern `^\d+/\d+$`; `commit_sha` 7–40 hex; timestamps RFC 3339.
3. JUnit conventions all three plugins must follow (written as a table in the doc):
   - Test identity parts: `classname`/`file` and `name` as each framework writes them, plus a `<property name="fq.test_key">` with the full §3.1 key so the backend never has to guess.
   - Attempts: one `<testcase>` per attempt with `<property name="fq.attempt" value="1">`, or the framework's native rerun elements, whichever M0-10 picks.
   - Tags: `<property name="fq.tags" value="critical,demo_flaky">`.
   - Skips: `<skipped message="...">` with the reason, plus `<property name="fq.skip_marker" value="skip|xfail|fixme|it.skip">`.
4. `docs/contracts/examples/`: one metadata JSON and one JUnit XML per framework (placeholders now, replaced by real spike output from M0-10).
5. OpenAPI: the FastAPI route in M1-01 must produce the same schema; add a note that `docs/contracts/` is the source and the route is checked against it in M1-01's tests.

**Out of scope.** Implementing the endpoint (M1-01) or the plugins (M1-06, M5-01, M5-02).

**Acceptance criteria**

- [ ] `metadata.schema.json` validates the §8.2 example and rejects one example per required field missing.
- [ ] The JUnit conventions table is final after M0-10 and every example file follows it.
- [ ] Idempotency key and every response code are documented with an example.
