**Context.** Five YAML files drive the system. The backend, the bot PR check and `fq-cli` all read them, so their schema must live in one place and reject bad input with clear messages.

**Implementation**

1. Pydantic v2 models in `backend/app/config/models.py`, all with `model_config = ConfigDict(extra="forbid", frozen=True)`, and a `version: Literal[1]` field on each file:
   - `TeamsConfig`: `teams: list[Team]` (slug, github\_team, jira {project\_key, component}, slack {channel, lead\_user\_id}, lead\_jira\_account\_id, product\_areas: list\[{name, paths: dict\[repo, list\[glob\]\]}\]), `levels` (path\_rules, job\_rules), `defaults` (every key in §5.1, with the §5.1 values as defaults).
   - `QuarantinePolicy`: `mode: Literal["shadow","enforce"]`, `never_quarantine` {paths, tests, markers}, `overrides` (subset of defaults).
   - `QuarantineList`: `tests: list[{id, jira, since: date, reason_suggested: Reason}]`.
   - `ReasonRules`: ordered `rules: list[{reason: Reason, exception_types: list[str], message_patterns: list[regex]}]`.
   - `MaskingRules`: `rules: list[{name, pattern: regex, replacement_type}]`.
   - Shared enums: `Reason` (the 9 reasons in §4.2), `Level` (unit, integration, api, e2e).
2. Validators beyond types:
   - exactly one team with slug `unowned`; slugs unique; globs and regexes compile; thresholds in range (0 < ratio ≤ 1, days > 0);
   - test IDs in `QuarantineList` and `never_quarantine.tests` match `{framework}::{path}::{name}` with framework in pytest/playwright/jest;
   - Jira keys match `^[A-Z][A-Z0-9]+-\d+$`; no duplicate test IDs.
3. `backend/app/config/loader.py`: `load_teams(path)`, `load_policy(path)`, etc. Each returns the model or raises `ConfigError` listing every problem as `file:line → field: message` (use `ruamel.yaml` to keep line numbers).
4. `merge_policy(defaults, overrides)` returning effective settings for one repo.
5. JSON Schema export: `fq-admin export-schemas` writes `config-example/schemas/*.schema.json` (for editor autocomplete and for `fq-cli`, which should not depend on the backend package). A CI check fails if the committed schemas are out of date.
6. `fq-admin validate-config <file>...` detects the file type from its name and prints all errors or "OK".
7. Complete example files in `config-example/`, matching §5 (including the `unowned` team), plus `config-example/invalid/` with one broken file per validator.

**Out of scope.** Loading config from the config repo (M2-02), using the values (later tasks).

**Acceptance criteria**

- [ ] Every example in `config-example/` validates.
- [ ] Every file in `config-example/invalid/` fails, and the message names the file, line and field.
- [ ] `merge_policy` returns §5.1 defaults when there are no overrides and the override value when there is one.
- [ ] Committed JSON Schemas match the models (CI check).
- [ ] Coverage of `app/config/` is at least 90%.

**Tests.** Parametrized tests over the valid and invalid example folders; `hypothesis` tests that random valid models round-trip through YAML unchanged.
