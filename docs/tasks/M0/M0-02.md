**Context.** AI coding agents do most of the implementation. They need one place that tells them the rules, and every issue and PR needs the same shape so work can be reviewed fast. **`CLAUDE.md` is already drafted at the repo root (2026-11-20) and is committed with M0-01;** this task reviews it against the final layout and commands from M0-01 and M0-05, adds `AGENTS.md`, and creates the templates below.

**Implementation**

1. `CLAUDE.md` at the root (also linked from `AGENTS.md` for other agents), with these sections:
   - **Project:** one paragraph and a link to `docs/architecture.md`; the section numbers in issues refer to it.
   - **Stack and commands:** the table from "Shared stack decisions" and the `make` commands.
   - **Layout rules:** `backend/app/domain/` is pure (no I/O, no DB, no HTTP, no clock: time is passed in); I/O lives in `integrations/`, `db/`, `api/`, `workers/`.
   - **Testing rules:** domain logic is written test-first; every bug fix starts with a failing test; no network in unit tests (use fakes or recorded fixtures); integration tests use the docker-compose Postgres.
   - **Style:** type hints everywhere, small functions, no catch-all `except`, no silent failures, structured logs with `upload_id` / `test_id` where they exist.
   - **Definition of done:** acceptance criteria ticked, tests added and green, `make lint typecheck test` green, docs updated if behaviour or config changed, PR links the issue.
   - **Don'ts:** no new dependencies without saying why in the PR, no changes outside the issue's scope, no secrets in code or fixtures.
2. `.github/ISSUE_TEMPLATE/task.yml` (issue form) with fields: Context, Implementation, Out of scope, Acceptance criteria (checkbox list), Tests, Depends on, Doc refs, Estimate. Plus `spike.yml` with: Question, Timebox, What to try, Deliverable, Decision to record.
3. `.github/pull_request_template.md`: Closes #, What changed, How it was tested, Checklist (DoD items), Screenshots/logs if relevant.
4. `docs/CONTRIBUTING.md`: branch naming `feat/M0-01/repo-skeleton` (per the git-workflow skill), conventional commit messages, squash-merge, one issue per PR.

**Out of scope.** Labels, milestones and the board (M0-03).

**Acceptance criteria**

- [ ] `CLAUDE.md` contains every section listed above.
- [ ] Opening a new issue on GitHub offers the Task and Spike forms with the listed fields.
- [ ] A new PR is pre-filled with the template.
- [ ] Dry run: an agent given only issue M0-04 and the repo finds the commands and the DoD without asking.
